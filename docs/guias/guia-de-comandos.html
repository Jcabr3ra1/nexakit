01
Antes de empezar · Terminal

Comprueba tus requisitos

Solo necesitas Node.js 24 o superior, Git (si vas a usar memoria por proyecto) y al menos uno de los tres clientes de IA instalados.

  • Node.js 24 o superior
  • npm con npx
  • Git (para crear memoria)
  • Claude Code, Codex o Antigravity CLI
  • Obsidian (opcional, para ver la bóveda)
Terminal · comprobar versiones
node --version
git --version

Verifica también el cliente que uses habitualmente: claude --version, codex --version o agy --version.

02
En tu proyecto · Una sola confirmación

Ejecuta npx nexakit en la carpeta del proyecto

NexaKit inspecciona la raíz y las subcarpetas inmediatas (package.json, pyproject.toml, requirements.txt, src-tauri/ y README.md), prepara una copia estable en ~/.nexakit y te hace tres preguntas.

Adapta los comandos a tu proyecto

Uso diario · Sin comandos previos para programar

Reinicia tu agente y empieza a trabajar

Cierra y vuelve a abrir tu agente para que cargue las skills, el MCP de memoria y las reglas globales de trabajo. A partir de ahí, habla y programa con total normalidad.

En Claude Code

Terminal · abrir proyecto

claude

En Codex

Terminal · abrir proyecto
cd '/ruta/a/mi-proyecto'
codex

En Antigravity

Terminal · abrir proyecto
cd '/ruta/a/mi-proyecto'
agy
  1. Programa normalmente, sin comando especial

    Pide la tarea directamente en el chat. La IA consulta la memoria del proyecto en solo lectura, crea rama, escribe pruebas e implementa sin que tengas que invocar ningún comando previo.

  2. Revisión automática al terminar cambios de código

    Cuando termina una tarea con cambios de código, la IA pide automáticamente una revisión en solo lectura a otra IA. La primera vez en la sesión te pregunta «¿A dónde mando la revisión?» marcando la recomendada y conserva tu respuesta el resto de la conversación. Si en una tarea dices «sin revisión», la omite. Si quieres pedir una revisión adicional en cualquier momento, escribe /revisar (o $revisar en Codex).

  3. Nota de seguimiento automática y cierre de memoria

    Si una tarea larga queda a medias (por pausa, cambio de IA, bloqueo o cierre), la IA escribe o actualiza la nota de seguimiento en 03-IMPLEMENTACION/Planes/<fecha>-<slug>-seguimiento.md dentro de la bóveda (pidiendo una sola autorización por sesión) y te indica cuándo conviene abrir una sesión nueva. Al fusionar en main, usa /cerrar-memoria (o $cerrar-memoria) para llevar las decisiones a las notas permanentes y marcar el seguimiento como completado.

El comando que necesitas

Busca por tarea o filtra por categoría. Todos los subcomandos funcionan directamente desde npx nexakit (o ~/.nexakit/nexakit tras el primer arranque).

No hay coincidencias. Prueba otra palabra o selecciona “Todas”.

Consulta también la referencia en Markdown o ejecuta npx nexakit --help.

Si algo no encaja

Quiero comprobar si todo está bien conectado o si quedó algo antiguo

Ejecuta npx nexakit comprobar. Verás un resumen con marcas ✓ y ! sobre tus clientes, skills base, enlaces de copias antiguas (reparables con npx nexakit reparar --desde <ruta>) y elementos retirados que ya no se usan.

Sale «Faltan las dependencias de esta copia. Ejecuta npm ci…»

Estás ejecutando un checkout local de desarrollo donde aún no se instalaron los paquetes de node_modules. Ejecuta npm ci en la carpeta que indica el mensaje.

El agente no ve las skills nuevas o las reglas globales

Cada IA lee sus skills, MCP e instrucciones globales al abrir la sesión. Cierra la sesión actual, abre una nueva y verifica el estado con npx nexakit comprobar y npx nexakit memoria status.

Quiero retirar lo que NexaKit instaló

Ejecuta npx nexakit quitar para ver qué enlaces, reglas globales y MCP creados por NexaKit se retirarían, y repite con npx nexakit quitar --si para aplicarlo sin tocar tus archivos propios.

Quiero revisar una skill antes de usarla

Ejecuta npx nexakit scan '/ruta/a/la-skill'. Revisa su contenido sin ejecutarla y avisa de caracteres ocultos, credenciales, descargas que se ejecutan o envío de datos. «Sin bloqueos» no garantiza que sea útil: una skill sin prueba funcional aparece como no probada.
